# 整篇渲染检查记录（2026-09-25）

本轮从逐个截图反馈改为整篇检查，修复链接、图片、目录、元数据、HTML 等共用渲染适配问题。新版程序：`release/render-audit/win-unpacked/Itypora.exe`。

## 检查依据与范围

- 样本：`examples/Markdown兼容性与显示测试.md`，23 个编号章节及前置说明。包含用户后来追加的空提示块和表格；不改写样本或填写其中的人工验收表。
- Typora 参照：用户提供的左右对照截图、本机 Typora 的文档可访问性文本、实际 Matcha / Matcha Dark 主题以及已安装 Typora 的基础样式。
- Itypora：1100×900 窗口，浅色/深色 × 即时渲染/所见即所得；按章节分段截图，长章节继续截图，合计 96 组章节记录。另有 680 像素窄窗口的渲染回归。
- Typora 原生截图接口报 `SetIsBorderRequired / 0x80004002`，无法取得同尺寸、同滚动位置的自动截图。因此本记录是差异排查和修复验证，不是两款软件逐像素一致的认证。
- [完整截图](../test-results/render-audit/after/index.html)；[Itypora 修复前后对照](../test-results/render-audit/compare.html)。前后对照两侧都是 Itypora，不将它冒充 Typora 基准。

## 本轮修复

| 问题 | 修复结果与验证 |
| --- | --- |
| 裸网址、中文标点后的邮箱未识别 | 补齐显示链接；代码、HTML 源码、已有链接不重复装饰；保存保留裸网址及邮箱源码形式 |
| 普通链接、引用式链接颜色不一致 | 两种编辑模式均匹配主题链接规则；验证实际计算颜色一致 |
| 链接悬停标题缺失 | 普通链接显示标题；引用式定义的标题通过解析器 AST 保留，修复编辑后标题丢失；验证编辑、保存及模式往返 |
| 独立图片靠左 | Markdown 图片与单独 HTML 图片居中，指定宽度有效；文字中的行内图片仍保留原布局 |
| 目录缺少主题外观、缩进叠加 | 接入主题目录样式，去除原生多余缩进及 ToC 标记 |
| 目录跳转目标不匹配 | 使用真实标题 ID，包括编辑器自动生成的后缀；验证点击定位 |
| YAML 被套上行内代码底色 | 使用元数据块样式，消除嵌套代码底色与字号干扰 |
| 脚注主题入口缺失 | 上标及脚注区域接入主题，去除原生边缘标记；避免字号重复缩小 |
| 代码高亮未使用主题的语法配色 | 将主题 CodeMirror token 选择器适配到 highlight.js；验证 Matcha 关键字实际颜色 |
| HTML 预览正文等宽、行内代码占整行 | HTML 正文恢复文档字体，行内代码恢复行内布局，保留安全清理和源码 |
| 只有标记的空提示块显示成普通引用 | 支持样本末尾的空 NOTE / CAUTION，保留主题标题及后续编辑能力 |

之前已修复的任务勾选、完成态、提示图标/中文标签、分隔线居中、表格填宽/内容列宽/虚线边框均重新检查。标题叶片沿用已有修复，本轮没有以旧截图重复改动。
